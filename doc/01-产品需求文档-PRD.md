# Agent IDE 产品需求文档 PRD

## 1. 文档信息

- 项目名称：Agent IDE
- 文档类型：第一版产品需求文档（PRD）
- 文档状态：V1 草案
- 日期：2026-05-17
- 目标：定义一个“类 Codex”的多 Agent 开发平台，支持内嵌浏览器自动化测试、AI 编码、多项目开发、Agent 协作，以及前后端项目联动。

## 2. 项目背景

传统 AI 编码工具往往只擅长单轮问答或单项目内代码生成，存在以下问题：

- 缺少完整的项目级工作区管理
- 无法原生联动浏览器做 UI 自动化测试
- 很难让多个 Agent 分工协作
- 前端项目和后端项目缺少统一的联调入口
- 缺少对代码执行、测试、日志、diff、回滚的完整闭环

本项目目标是构建一个面向真实开发场景的 Agent IDE，让用户可以在一个统一平台内完成“理解项目、修改代码、启动服务、打开浏览器、执行测试、观察结果、继续修复”的整条链路。

## 3. 产品定位

Agent IDE 是一个桌面优先的智能开发平台，既是：

- 开发助手
- 多项目工作区管理器
- 浏览器自动化测试控制台
- 多 Agent 协作运行时
- 前后端联调编排平台

## 4. 产品目标

### 4.1 业务目标

- 降低本地多项目开发与联调成本
- 提高编码、调试、测试自动化效率
- 提供可追踪、可回放、可审计的 Agent 执行链路
- 形成后续插件化、平台化扩展基础

### 4.2 用户目标

- 用户可以让 Agent 理解并修改真实项目代码
- 用户可以在内嵌浏览器中完成自动化测试
- 用户可以同时管理多个前后端项目
- 用户可以把一个任务拆分给多个 Agent 协作完成
- 用户可以让系统自动串联“改代码 -> 启服务 -> 测页面 -> 修问题”

## 5. 目标用户

### 5.1 核心用户

- 全栈开发工程师
- 前端工程师
- 后端工程师
- 测试开发工程师
- AI 编程工具重度用户

### 5.2 使用场景

- 修改前端页面并立即在浏览器验证
- 调整后端接口后联动前端项目测试
- 在多仓库/多项目环境中同时开发
- 把“编码、测试、审查”分配给不同 Agent
- 用自然语言触发浏览器自动化脚本

## 6. 第一版范围

第一版范围全部包含以下能力，不做功能裁剪，只做实现优先级排序。

### 6.1 必须实现的核心能力

1. 内嵌浏览器
2. 浏览器自动化测试
3. AI 编写代码
4. 多项目工作区开发
5. Agent 对接 Agent
6. 后端项目对接前端项目
7. 任务执行日志与结果追踪
8. 代码 diff 预览与应用
9. 命令执行与运行结果回传
10. 测试、构建、运行的闭环操作

### 6.2 第一版暂不纳入范围

- 团队多人实时协作编辑
- 云端托管型项目运行环境
- 插件市场
- 自动部署到生产环境
- 移动端 App

## 7. 功能需求

以下以 `FR` 编号管理功能范围。

### 7.1 工作区与多项目管理

#### FR-01 工作区管理

系统应支持创建 Workspace，并在一个 Workspace 内管理多个项目。

要求：

- 支持添加本地项目目录
- 支持识别 Git 仓库
- 支持配置项目名称、类型、根目录
- 支持保存项目级命令模板
- 支持项目分组展示

#### FR-02 项目类型识别

系统应支持识别至少以下项目类型：

- 前端项目：React、Vue、Next.js、Vite、静态站点
- 后端项目：Node.js、Java、.NET、Python
- 通用项目：仅作为代码目录管理

#### FR-03 多项目联动

系统应支持在一个 Workspace 内定义项目关联关系。

要求：

- 支持指定某个前端项目依赖某个后端项目
- 支持配置环境地址映射
- 支持一键启动关联项目
- 支持保存常用联调组合

### 7.2 AI 编码能力

#### FR-04 项目理解

Agent 应具备以下能力：

- 遍历项目结构
- 搜索文件与代码片段
- 理解符号、模块、引用关系
- 汇总上下文后生成修改方案

#### FR-05 代码编辑

Agent 应支持：

- 创建文件
- 修改文件
- 删除文件
- 生成补丁 diff
- 预览改动
- 用户确认后应用改动

第一版补充规则：

- 默认采用“先生成 patch，再由用户确认是否落盘”的模式
- 低风险改动可支持用户开启自动应用，但默认关闭
- 删除文件、批量改写文件、跨项目改写文件必须强制二次确认
- 每次改动都必须关联任务 ID、Agent ID 和文件 diff 记录
- 同一时刻同一文件只允许一个 Coder Agent 持有写入租约，避免并发覆盖

#### FR-06 执行验证

Agent 修改代码后应支持：

- 运行构建命令
- 运行测试命令
- 运行 lint/format 命令
- 返回结构化结果

### 7.3 内嵌浏览器与自动化测试

#### FR-07 浏览器容器

系统应提供内嵌浏览器视图，支持：

- 打开本地地址和远程地址
- 标签页管理
- 页面刷新
- 前进/后退
- 截图

#### FR-08 浏览器自动化动作

系统应支持 Agent 控制浏览器执行：

- 打开页面
- 点击元素
- 输入文本
- 选择下拉项
- 上传文件
- 等待元素出现
- 执行断言
- 截图和保存结果

#### FR-09 浏览器调试信息

系统应支持采集：

- Console 日志
- Network 请求
- 页面报错
- 截图记录
- 自动化步骤日志

#### FR-10 测试脚本化

系统应支持：

- 将自然语言测试任务转成自动化步骤
- 导出测试脚本
- 保存测试用例
- 回放历史测试

第一版补充规则：

- 浏览器自动化默认基于统一的步骤模型执行，而不是直接暴露底层引擎脚本
- 导出的测试脚本格式第一版统一为 Playwright 脚本
- 历史回放至少应包含步骤序列、断言结果、截图和失败位置
- 需要明确区分“用户手动浏览页面”和“Agent 自动化操作页面”的上下文关系

### 7.4 多 Agent 协作

#### FR-11 Agent 角色体系

第一版至少支持以下角色：

- Coordinator Agent：负责任务拆解与调度
- Coder Agent：负责代码理解与修改
- Browser Agent：负责浏览器测试与页面检查
- Review Agent：负责改动审查与风险提示

#### FR-12 Agent 间通信

系统应支持 Agent 之间通过结构化消息协作。

要求：

- 发送任务
- 返回结果
- 共享摘要上下文
- 标记状态
- 附带引用产物（diff、日志、截图、文件）

第一版补充规则：

- Agent 间传递的是结构化摘要和产物引用，不直接共享无限上下文
- Coordinator Agent 负责子任务编排、结果汇总和最终仲裁
- 多个 Agent 不允许同时写同一文件；若存在冲突，由 Coordinator 重新分配或串行执行
- Review Agent 默认是阻断型角色：发现高风险问题时，可阻止改动进入“已完成”状态

#### FR-13 子任务分发

Coordinator Agent 应支持：

- 将任务拆成多个子任务
- 指定子任务目标 Agent
- 跟踪子任务进度
- 合并子任务结果

### 7.5 前后端项目对接

#### FR-14 前后端绑定

系统应支持将一个前端项目与一个或多个后端项目建立绑定。

要求：

- 配置接口根地址
- 配置本地端口
- 配置启动顺序
- 配置依赖健康检查地址

第一版补充规则：

- 一个前端项目可绑定多个后端服务、BFF 服务或 Mock 服务
- 绑定关系必须支持环境维度，例如 `local`、`test`、`staging`
- 每个绑定项都需要独立配置：项目 ID、服务类型、端口、基础地址、健康检查地址、启动顺序
- 联调时由系统按绑定关系生成启动计划和等待策略

#### FR-15 联调模式

系统应支持联调模式：

- 同时启动前后端
- 等待服务可用
- 自动打开指定页面
- 执行预设浏览器测试
- 收集联调日志

### 7.6 任务与会话系统

#### FR-16 任务管理

系统应支持：

- 创建任务
- 暂停任务
- 取消任务
- 重试任务
- 查看任务状态
- 查看任务结果

第一版补充规则：

- 系统应支持显式的 `Plan Mode`、`Execute Mode`、`Long Run Mode`
- `Plan Mode` 下只允许扫描、分析、拆解和生成计划，不执行副作用操作
- `Execute Mode` 下按批准后的计划执行，可包含代码修改、命令执行、浏览器测试
- `Long Run Mode` 下任务可进入后台持续执行，并支持恢复、通知和中途人工接管
- 长任务应支持检查点保存，至少在计划生成后、patch 审批后、构建完成后、浏览器测试完成后记录恢复点
- 任务状态除基础状态外，还应支持 `planned`、`blocked`、`retrying`

#### FR-17 会话记录

系统应保存：

- 用户输入
- Agent 推理摘要
- 工具调用记录
- 文件改动记录
- 浏览器操作轨迹
- 命令执行结果

第一版补充规则：

- 会话系统必须支持上下文压缩，避免长对话导致上下文失控
- 必须区分 `实时上下文`、`压缩摘要上下文`、`可检索项目记忆`
- 用户或系统应支持固定 `Pinned Context`，被固定内容不得被普通压缩流程移除
- 压缩摘要至少包含：目标、已完成步骤、未完成步骤、关键决策、失败原因、待确认事项、引用产物

### 7.7 权限与安全

#### FR-18 执行权限控制

系统应对以下行为进行权限管理：

- 终端命令执行
- 文件写入
- 删除文件
- 安装依赖
- Git 操作
- 浏览器访问外网

第一版补充规则：

- 权限至少分为全局、Workspace、Project、Agent 四个作用域
- 用户确认支持三种粒度：本次允许、当前会话允许、永久允许
- 高风险命令必须经过命令策略层判定，不得仅依赖 Agent 自主判断
- 浏览器外网访问建议支持域名白名单

#### FR-19 敏感信息保护

系统应具备：

- 环境变量脱敏展示
- 日志中的密钥脱敏
- 可配置的命令黑名单
- 高风险操作确认机制

### 7.8 运行模式设计

#### FR-20 规划模式

系统应提供显式规划模式。

要求：

- 在执行前先理解需求和扫描上下文
- 生成任务树、依赖关系和风险点
- 标记哪些步骤需要用户确认
- 展示预计涉及的项目、文件、命令、浏览器动作
- 支持用户批准、修改或仅执行某一子步骤

#### FR-21 长任务执行模式

系统应提供长任务执行模式。

要求：

- 支持前台执行和后台执行
- 支持长时间构建、测试、联调和浏览器自动化
- 支持断点恢复
- 支持实时日志流
- 支持任务完成通知
- 支持失败后从最近检查点恢复或重试

#### FR-22 上下文压缩与记忆模式

系统应支持长会话上下文治理。

要求：

- 自动压缩历史对话、日志和中间推理
- 保留关键业务决策和产物引用
- 支持项目级记忆和 Workspace 级记忆
- 支持按任务或主题检索历史记忆
- 支持固定上下文不被压缩

### 7.9 平台辅助能力

#### FR-23 模型管理

系统应提供模型管理能力。

要求：

- 支持为不同 Agent 指定不同模型
- 支持模型能力标签，例如速度优先、质量优先、低成本优先
- 支持默认模型、备用模型和失败回退模型
- 支持记录模型调用成本、耗时和失败率
- 支持在 Workspace 级别覆盖全局模型策略

#### FR-24 环境配置中心

系统应提供统一环境配置中心。

要求：

- 支持为每个项目配置开发、测试、预发等环境
- 支持保存端口、启动命令、构建命令、测试命令、健康检查地址
- 支持为前后端绑定关系配置环境映射
- 支持保存环境变量引用和敏感配置引用
- 支持一键切换当前 Workspace 的运行环境

#### FR-25 审批中心

系统应提供审批中心。

要求：

- 展示所有待审批的 patch、命令、Git 写操作、浏览器登录态同步请求
- 支持批准、拒绝、延后处理
- 支持查看审批原因、发起 Agent、关联任务和风险说明
- 支持审批历史查询
- 支持按权限策略自动判断是否进入审批队列

#### FR-26 记忆管理面板

系统应提供记忆管理面板。

要求：

- 支持查看 Workspace 级和项目级记忆
- 支持新增、编辑、删除记忆条目
- 支持固定关键记忆
- 支持标记错误记忆并禁止继续召回
- 支持查看某条记忆来源于哪些任务、摘要或产物

#### FR-27 恢复与回滚

系统应提供恢复与回滚能力。

要求：

- 支持回滚最近一次 patch
- 支持按任务恢复到指定检查点
- 支持重新执行失败步骤而非整任务重跑
- 支持对浏览器自动化从某一步开始重试
- 支持展示回滚影响范围和恢复前后差异

## 8. 非功能需求

### 8.1 性能

- 单项目首次索引时间应可接受，目标小于 2 分钟
- 常规代码检索响应时间目标小于 3 秒
- 自动化测试步骤执行具备可视反馈
- 增量索引应优先于全量重建，目标在常规改动后 10 秒内完成索引刷新

### 8.2 稳定性

- 任务失败需可定位
- 浏览器自动化失败需可复现
- 多 Agent 任务需可追踪状态
- 长时运行任务在桌面端刷新或 UI 重载后不应丢失执行状态
- 长任务在应用重启后应至少具备恢复元数据和结果追踪能力

### 8.3 可观察性

系统应记录：

- Agent 调用链
- 工具调用日志
- 文件 diff
- 浏览器截图
- 网络错误
- 执行时长
- 权限确认记录
- 文件写入审批记录
- 上下文压缩记录
- 长任务恢复点记录

### 8.4 可扩展性

架构需预留：

- 新 Agent 类型接入
- 新工具接入
- 新语言/新项目类型支持
- 云端任务运行能力
- 模型提供方扩展能力
- 环境模板扩展能力

## 9. 典型用户流程

### 场景 A：修改前端页面并自动验证

1. 用户在 Workspace 中选择前端项目
2. 用户输入需求，例如“修改登录页按钮样式并验证”
3. Coordinator 分派 Coder Agent 改代码
4. Coder Agent 修改文件并执行构建
5. Browser Agent 打开内嵌浏览器验证页面
6. Browser Agent 输出截图、日志、断言结果
7. Review Agent 汇总改动与风险

### 场景 B：前后端联调修复

1. 用户选择前端项目和后端项目
2. 用户输入“修复订单提交失败”
3. Coordinator 拆分为接口排查、前端提交流程排查、浏览器复现
4. 多个 Agent 分别执行
5. 系统自动启动前后端服务
6. 浏览器复现场景并抓取错误日志
7. Coder Agent 修复后再次联调验证

### 场景 C：先规划再执行

1. 用户输入一个复杂需求
2. 系统进入 `Plan Mode`
3. Coordinator 扫描项目、拆解任务、评估依赖
4. 系统展示任务树、风险点、预计修改范围
5. 用户选择批准全部或只批准部分步骤
6. 系统切换到 `Execute Mode` 或 `Long Run Mode`

### 场景 D：长任务后台执行

1. 用户发起包含构建、联调、浏览器测试的复杂任务
2. 系统将任务切换到 `Long Run Mode`
3. 后台持续执行并写入检查点和日志
4. 用户可关闭当前面板后稍后回来查看进度
5. 若中途失败，系统支持从最近检查点恢复

### 场景 E：审批与回滚

1. Agent 生成 patch 和高风险命令计划
2. 系统将请求送入审批中心
3. 用户查看风险说明并选择批准或拒绝
4. 若执行后结果异常，用户可选择回滚最近 patch 或恢复到指定检查点

### 场景 F：模型与环境切换

1. 用户进入环境配置中心
2. 切换当前 Workspace 到目标环境
3. 系统自动应用对应端口、命令、接口地址和健康检查
4. 用户在模型管理中为 Browser Agent 或 Coder Agent 切换模型策略
5. 后续任务按新的环境和模型配置运行

## 10. 验收标准

### 10.1 功能验收

以下项全部通过才视为第一版核心能力完成：

- 可以创建 Workspace 并添加多个项目
- 可以定义前后端项目关联关系
- Agent 可以读取、修改并保存代码
- 可以生成并查看 diff
- 可以运行构建/测试/命令并返回结果
- 可以在内嵌浏览器打开页面并执行自动化步骤
- 可以采集 console、network、截图
- 可以由 Coordinator 分发给多个 Agent
- 可以查看任务链路和执行记录
- 可以在代码落盘前完成 patch 预览与确认
- 可以阻止两个 Agent 同时改写同一文件
- 可以对一个前端项目绑定多个后端服务并完成联调启动
- 可以显式进入 `Plan Mode` 并生成可批准的任务计划
- 可以执行 `Long Run Mode` 并在重载后继续追踪任务
- 可以对长会话执行上下文压缩且保留关键决策与引用
- 可以为不同 Agent 配置不同模型并查看模型调用记录
- 可以在环境配置中心切换项目环境并驱动联调配置生效
- 可以在审批中心集中处理 patch、命令、Git、登录态同步请求
- 可以在记忆管理面板查看、修正和固定记忆条目
- 可以对任务执行结果进行恢复或回滚

补充验收口径：

- 至少支持在一个 Workspace 中管理 10 个项目
- 至少支持同时运行 3 个项目实例并可追踪端口与健康状态
- 浏览器自动化至少覆盖 `goto`、`click`、`type`、`waitFor`、`assertText`、`screenshot`
- 每次代码修改必须能追溯到任务、Agent、时间和 diff
- 长任务至少支持 1 次中断后恢复元数据
- 压缩后的上下文仍能正确恢复任务目标、当前阶段和待确认事项
- 至少支持一个全局默认模型和每个 Agent 的单独模型覆盖
- 至少支持 `local`、`test`、`staging` 三类环境配置
- 审批中心必须能追溯审批人、审批时间和审批对象
- 回滚操作必须能展示影响文件和目标检查点

### 10.2 体验验收

- 用户能清楚知道当前哪个 Agent 在执行什么
- 用户能清楚看到哪些文件被改动
- 用户能清楚回看浏览器测试过程和结果
- 用户能在失败后继续追踪原因并重试

## 11. 风险与依赖

### 11.1 风险

- 多 Agent 并发导致上下文混乱
- 浏览器自动化稳定性不足
- 大项目索引性能不足
- 模型输出不稳定导致误改代码
- 高权限命令存在安全风险

### 11.2 关键依赖

- 大模型接口能力
- 代码索引与搜索能力
- 浏览器自动化引擎
- 本地终端执行能力
- 本地文件系统访问能力

## 12. 版本交付建议

虽然第一版功能全部要做，但建议内部按四个里程碑推进：

### M1 基础底座

- Workspace
- Project
- Session
- Task
- 终端执行
- 文件读写

### M2 编码闭环

- 代码索引
- 代码搜索
- diff 预览
- 构建测试执行
- Review Agent

### M3 浏览器闭环

- 内嵌浏览器
- 浏览器自动化
- 截图/日志/网络抓取
- 测试用例保存

### M4 多 Agent 与联调闭环

- Agent 对接 Agent
- 前后端项目绑定

- 全链路追踪

### M5 规划与长任务闭环

- Plan Mode
- Long Run Mode
- 检查点恢复
- 上下文压缩

### M6 平台治理闭环

- 模型管理
- 环境配置中心
- 审批中心
- 记忆管理面板
- 恢复与回滚

## 13. 结论

第一版产品不是单纯的“AI 写代码工具”，而是一个具备代码执行、浏览器控制、项目编排、Agent 协作和联调能力的完整开发平台。后续设计与开发必须围绕“闭环能力”展开，而不是只围绕单点生成能力展开。
